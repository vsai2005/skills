# Change Contract

For non-trivial work, establish this compact contract before large edits.

```text
Outcome:
Acceptance evidence:
Primary mode:
Expected owners/files:
Contracts to preserve:
Non-goals:
Risk hotspots:
Verification plan:
```

The contract is not a bureaucracy step. Keep it short enough to update when evidence changes.

## Good acceptance evidence

Prefer observable statements:

- request with invalid token returns 400 and stable error shape;
- React form preserves current values after failed save;
- parser classifies technology names without special-casing individual fixtures;
- migration can read existing rows and new rows;
- all callers of the shared validator still satisfy the contract.

Avoid vague acceptance criteria such as "make robust" or "clean it up" without specifying observable consequences.
