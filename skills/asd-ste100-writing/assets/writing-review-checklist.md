# Technical Writing Review Checklist

## Meaning

- [ ] Technical meaning is unchanged.
- [ ] Numbers, units, limits, warnings, identifiers, commands, and error codes are preserved.
- [ ] No safety, security, legal, or compatibility condition was simplified away.

## Terminology

- [ ] One term is used consistently for one concept.
- [ ] Official API, UI, product, schema, and code names are unchanged.
- [ ] Uncommon domain terms are defined when needed.

## Sentences

- [ ] Each sentence has one main action or idea where practical.
- [ ] Instructions use direct verbs.
- [ ] Conditions appear before dependent actions.
- [ ] Ambiguous pronouns are removed.
- [ ] Sentence length is reasonable for the default 80% mode.

## Readability

- [ ] Unnecessary formal phrases are removed.
- [ ] Lists are used only when they improve scanning.
- [ ] The result sounds clear and professional, not artificially mechanical.

## Compliance wording

- [ ] The text says `ASD-STE100-inspired` unless verified against an authorized official specification.
- [ ] The result does not claim ASD-STE100 certification solely because this skill was used.
