# Rewrite Workflow

Use this workflow when the task needs more than a tiny wording cleanup.

## 1. Establish the contract

Identify:

- audience;
- purpose;
- genre;
- facts and literals that must not change;
- intended point of view;
- requested intensity: Light, Standard, or Deep;
- whether an authentic voice sample is available.

If the user did not choose an intensity, use **Standard** unless the text is already good enough for Light.

## 2. Audit the source

Diagnose the actual problems before changing anything.

Useful questions:

- Does the opening delay the real point?
- Are transition words doing work that sentence order should do?
- Are several sentences built with the same shape?
- Are the paragraphs suspiciously uniform?
- Are claims vague because the source lacks evidence, or because concrete evidence was ignored?
- Is the prose too formal for the audience?
- Is the prose already natural enough?

If nothing meaningful fired, stop. Do not manufacture a rewrite.

## 3. Build a voice target

If an authentic sample exists, observe measurable tendencies instead of copying phrases:

- sentence-length range;
- paragraph length;
- contraction use;
- first/second-person frequency;
- explicit transitions;
- punctuation habits;
- vocabulary density.

If no sample exists, preserve the voice already present in the source and match the genre.

## 4. Rewrite from the original

Always use the original source as the semantic anchor.

Do not:

```text
original -> rewrite 1 -> rewrite 2 -> rewrite 3
```

Prefer:

```text
original -> candidate A
original -> candidate B   # Deep mode only when useful
```

This reduces accumulated semantic drift.

## 5. Apply the selected intensity

### Light

- remove obvious filler;
- fix repetitive transitions;
- smooth awkward wording;
- preserve structure and most phrasing.

### Standard

- change sentence order where logic improves;
- combine or split sentences as needed;
- adjust paragraph boundaries;
- replace abstract wording with source-supported specifics.

### Deep

- reorganize sections when the current structure is strongly templated;
- use an authentic voice profile when available;
- create two candidates only when the tradeoff is meaningful;
- compare each candidate against the original, not against the other rewrite.

## 6. Run two separate review passes

### Pass A — preservation

Check facts, numbers, names, dates, quotes, code, commands, citations, negation, modality, and uncertainty.

### Pass B — writing quality

Ask whether the result is actually better writing:

- clearer;
- more natural;
- more specific;
- appropriate for the genre;
- less repetitive;
- no longer than necessary.

A text can be less machine-like and still be worse writing. Do not confuse those goals.
